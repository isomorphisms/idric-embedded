# WebGPU platform architecture handoff

Status: 2026-08-27

## Classification

WebGPU is a portable GPU API/runtime boundary, not a processor ISA. WGSL is its shader language, not native GPU bytecode.

The compiler-facing architecture inventory and WGSL backend now live in:

- [`isomorphisms/idris-shader-backend:target/webgpu-wgsl`](https://github.com/isomorphisms/idris-shader-backend/tree/target/webgpu-wgsl)

That branch is the single canonical home for WGSL types, operations, built-ins, feature gates, memory/execution semantics, and the WebGPU shader/pipeline/resource API surface.

## What remains here

This branch exists only to preserve the host/deployment relationship to the embedded/Wasm work:

```text
Idriç host code
    ↓
Wasm or another host backend
    ↓
browser/native WebGPU-capable runtime
    ↓
WebGPU host API

Idriç shader subset
    ↓
idris-shader-backend target/webgpu-wgsl
    ↓
WGSL
    ↓
WebGPU implementation
    ↓
native graphics stack / GPU
```

The two compiler paths should remain separate. Wasm handles CPU-like host computation; WGSL handles explicitly GPU shader computation. WebGPU is the runtime bridge, not a fictional shared instruction set.

## Platform questions still appropriate here

- which browser/native runtime is the reproducible acceptance host;
- how an Idriç/Wasm host obtains and initializes WebGPU;
- packaging/loading WGSL generated by the shader repository;
- browser/worker boundaries;
- host-side asset/module loading;
- how a WebGPU-capable deployment is exercised in CI or on an actual target device.

Do not duplicate the complete WGSL/WebGPU language/API inventory here. Follow the shader target branch instead.
